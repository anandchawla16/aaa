# Competency Model — AI Transformation Lead

Eight competencies. Each is assessed at four levels. The programme moves a
participant from **Aware** to **Practising** across all eight, and to
**Leading** on at least three.

| Level | Meaning |
|---|---|
| **1 · Aware** | Can describe it. Cannot yet do it unaided. |
| **2 · Practising** | Does it correctly on a supplied case, with a checklist. |
| **3 · Leading** | Does it unaided on their own group's messy reality, and can teach it. |
| **4 · Institutionalising** | Has changed how the function works. Others do it without them. |

---

## C1 — Workflow diagnosis

Seeing a function as a set of workflows, each with a volume, a cost, a failure
mode and an owner; and telling apart work that is genuinely AI-shaped from work
that merely feels tedious.

| Level | Looks like |
|---|---|
| 1 | Lists "tasks" without volume, owner, or failure mode. |
| 2 | Produces a scored inventory using the VFRR frame (Volume, Friction, Risk, Readiness) for a supplied function. |
| 3 | Does it live with a function head who disagrees, and defends the scoring. |
| 4 | The function maintains its own inventory and re-scores it quarterly. |

**Assessed in:** Module 1 (Ex 1.1), Module 2, Module 6 capstone.

---

## C2 — Capability calibration

Knowing what a model reliably does, what it does but must be checked, and what
it must never be trusted with — and being able to demonstrate the boundary
rather than assert it.

| Level | Looks like |
|---|---|
| 1 | Repeats "it can hallucinate." |
| 2 | Correctly sorts tasks into the four trust tiers and can make the model fail on demand. |
| 3 | Predicts *in advance* where a specific workflow will break, and designs the check for it. |
| 4 | The function's own staff run a verification step by habit. |

**Assessed in:** Module 1 (Ex 1.2, Ex 1.4).

---

## C3 — Prompt architecture

Writing instructions that are reproducible by someone else, grounded in a named
source of truth, explicit about output shape, and explicit about what to do when
the data does not support an answer.

| Level | Looks like |
|---|---|
| 1 | Writes a request. |
| 2 | Writes a CRISP-structured prompt with a refuse-to-guess clause and acceptance criteria. |
| 3 | Writes prompts that a different person runs a month later and gets the same quality. |
| 4 | The function has a prompt library it maintains itself. |

**Assessed in:** Module 1 (Ex 1.3), Module 2, Module 3.

---

## C4 — Grounding and data handling

Attaching the right source of truth, knowing the defects in an export before
trusting a total, and never letting the model supply an institutional fact from
memory.

| Level | Looks like |
|---|---|
| 1 | Uploads a file and accepts the answer. |
| 2 | Normalises known defects, cites clause numbers, spot-checks totals independently. |
| 3 | Anticipates the defect classes in an unfamiliar export and writes the pre-flight check. |
| 4 | Exports are cleaned at source because the Lead pushed the fix upstream. |

**Assessed in:** Module 1 (Ex 1.4, Ex 1.5, Ex 1.6), Module 3.

---

## C5 — Building reusable assets inside Claude

Turning a prompt that worked once into something a non-technical colleague runs
every week — a Project with standing context, a Skill, a checked artifact.

| Level | Looks like |
|---|---|
| 1 | Re-types the prompt each time. |
| 2 | Specifies a reusable asset: trigger, inputs, steps, output, failure behaviour. |
| 3 | Builds it, hands it over, and it survives a month without them. |
| 4 | Function owners build their own. |

**Assessed in:** Module 1 (Ex 1.7), Module 4.

---

## C6 — Risk, privacy and governance

Applying the Never List, the Approved Systems List and DPDP-shaped obligations
to a live workflow; red-teaming your own build before someone else does.

| Level | Looks like |
|---|---|
| 1 | Knows there are rules. |
| 2 | Redacts correctly, classifies a workflow into the right lane, finds three ways their own prompt could produce harm. |
| 3 | Refuses a senior stakeholder's request and offers a compliant alternative. |
| 4 | The guardrails are policy, and the function applies them without being asked. |

**Assessed in:** Module 1 (Ex 1.8), Module 5.

---

## C7 — Evidence and value proof

Measuring before, measuring after, attributing honestly, and reporting a
negative result when that is what happened.

| Level | Looks like |
|---|---|
| 1 | Reports enthusiasm and adoption counts. |
| 2 | Establishes a baseline before building, and computes the delta after. |
| 3 | Ties the delta to a Board priority and survives the CFO's challenge. |
| 4 | The measure is in the function's own dashboard. |

**Assessed in:** Module 4, Module 6.

---

## C8 — Change leadership in a school context

Working with principals and teachers who are time-poor, sceptical and
accountable to parents; handing over rather than owning; and knowing when the
answer is no.

| Level | Looks like |
|---|---|
| 1 | Presents the technology. |
| 2 | Runs a handover with a written run-book and a named owner. |
| 3 | Recovers a workflow that a campus abandoned, and diagnoses why honestly. |
| 4 | Campuses request the next workflow themselves. |

**Assessed in:** Module 6, and continuously in facilitator observation.

---

## Certification bar

| Award | Requirement |
|---|---|
| **Module 1 Foundation** | ≥ 70% on the Module 1 assessment, all eight exercises submitted |
| **Practitioner** | Modules 1–4 complete; Level 2 on all eight competencies |
| **AI Transformation Lead (certified)** | Modules 1–6; Level 3 on at least C1, C3, C4 and C6; capstone workflow in production use for 30 days with evidence |

Certification is withheld — regardless of score — for any participant who
places real student, parent or employee personal data into an unapproved system
during the programme. This is stated on day one and enforced.
