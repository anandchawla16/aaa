# Training Data Pack — Meridian Group of Schools

Everything in this folder is **synthetic**. It was generated by
[`../tools/gen_data.py`](../tools/gen_data.py) with a fixed random seed, so it
is reproducible and identical for every cohort. No real person, student,
employee, vendor or school appears in it.

You upload these files to Claude during the exercises. Nothing else is needed —
no database, no BI tool, no scripts.

## Why the data is messy on purpose

Every file carries the same defects your group's real ERP exports carry. If the
data were clean, the exercises would teach the wrong lesson: that AI work is
about clever prompting. It is not. It is mostly about **knowing what is wrong
with your inputs before you trust an output.**

Planted defects, by design:

- Campus names are inconsistent (`Pune-Baner`, `Pune - Baner`, `PUNE BANER`,
  `Pune Baner`; `Bengaluru-Whitefield` vs `Bangalore-Whitefield`). Any
  campus-level total is wrong until these are normalised.
- Source names in the CRM export vary in case (`Google Ads` / `google ads`).
  Group by the raw column and your channel report double-counts.
- Dates appear in three formats and some are blank.
- Amounts appear both as `125000` and as `1,25,000`; some are blank.
- There are duplicate rows and duplicate identities.
- One fee balance is negative (an advance/credit).
- One vendor quotes GST-inclusive rates without a flag in the obvious place.
- One vendor's quotation is incomplete; another under-quotes a quantity.

**None of these are labelled.** Finding them is the exercise.

## Files

### `group-fact-sheet.md`
The group's profile, org structure, systems, Board priorities and constraints.
This is the standing context you attach to almost every prompt. Read it first.

### `hr-service-and-leave-policy.md`
Extract of policy MGS/HR/POL/07 v4.2 — probation, leave, notice period,
appraisal, data confidentiality. Contains provisions that deliberately differ
from industry norms, so that ungrounded answers are visibly wrong.

### `accounts-fee-policy-circular.md`
Fee due dates, late fee, the seven-stage collection escalation ladder,
concession slabs, and the non-negotiable conduct rules for fee communication.

### `purchase-requests-inbox.txt`
Raw, unstructured purchase requests — WhatsApp forwards and email fragments,
partly in Hinglish, with missing budget heads, missing approvals, scope creep,
a single-source case and one purchase already made without approval.

### `hr_staff_roster.csv` — 91 rows
| Column | Notes |
|---|---|
| `emp_id` | `MGS-1xxx`. One person appears twice under two IDs. |
| `employee_name` | Some values have leading/trailing whitespace |
| `campus` | Inconsistent naming |
| `department` | Academic / Administration / Accounts / Marketing / Purchase / Support |
| `designation`, `grade` | |
| `date_of_joining` | Three date formats; 3 blanks |
| `employment_type` | Permanent / Probation / Contract / Visiting |
| `qualification`, `subject_taught` | `subject_taught` blank for non-academic |
| `ctc_annual_inr` | Mixed plain and Indian-format; 3 blanks |
| `confirmation_status` | Confirmed / Pending / N/A |
| `last_appraisal_rating` | A / B / C / D, some blank |
| `official_email` | |

### `accounts_fee_ledger.csv` — 142 rows
Invoice-level fee position as at **8 September 2026**.
Key columns: `amount_due_inr`, `amount_paid_inr`, `balance_inr`,
`days_overdue`, `concession_type`, `parent_contact_preference`, `remarks`.
Contains 50 rows with an outstanding balance, one credit balance, one exact
duplicate row, and RTE rows with zero due.

### `purchase_requisition.csv` — 12 rows
What Pune-Baner actually needs for Science Block Phase 2: item code,
description, unit, `quantity_required`, `required_by_date` (15 Nov 2026),
budget head.

### `purchase_vendor_quotations.csv` — 46 rows
Four vendors against those 12 items.
`rate_basis` tells you whether `unit_rate_inr` is inclusive or exclusive of
GST — **read it before comparing anything**. Item descriptions are worded
differently by each vendor for the same item. One vendor omits two line items;
another quotes a lower quantity than required.

### `marketing_admission_enquiries.csv` — 2,518 rows
Admission enquiries, May–Aug 2026, all 14 campuses.
Key columns: `source`, `status`, `followup_count`, `lost_reason`, `counsellor`.
Statuses run New → Contacted → Visit Scheduled → Visited → Application Started
→ Admitted, with Lost and Not Reachable as terminal states.
Roughly 5% of `enquiry_date` values are blank.

### `marketing_channel_spend.csv` — 280 rows
Marketing spend by campus × month × channel, May–Aug 2026. Joins to the
enquiries file on campus — **after** you normalise campus names on both sides.

### `academic_assessment_results.csv` — 420 rows
Assessment results with `marks_obtained`, `max_marks`, `attendance_pct` and
`teacher`. Marks generally track attendance. One teacher's results do not —
which is only visible if you segment by teacher rather than by campus.

## Regenerating

```bash
python3 tools/gen_data.py     # writes to tools/out/, seed 20260908
```

The seed is fixed, so regenerating produces byte-identical files. If you change
the generator, update the answer keys in
[`../module-01-foundations/facilitator-answer-key.md`](../module-01-foundations/facilitator-answer-key.md),
because the numbers there are computed from this exact data.

## Ground rule for the whole programme

You may use this synthetic pack freely in Claude. You may **not** substitute
your group's real staff, student, parent or vendor data until you have
completed Module 5 and your Approved Systems List and consent position have
been confirmed in writing. That rule is itself part of the curriculum.
